---
name: Independent time tracking and manual hours
description: Product rules for independent time classifications, timer activation, privacy, and manual worked-time.
---

A separate organization-level timer module is disabled by default. At ticket creation, client billing and collaborator recognition are independent options; either one starts tracking, and choosing neither leaves the ticket untracked. Admins can change either classification later and activate tracking on an existing ticket. A later classification change applies to future sessions and must not rewrite historical session snapshots. Non-admins may see the timer-recorded duration they're authorized to view, but not whether it is billable or recognizable. When the module is off, timer, classification, and report controls are hidden and API writes are blocked, while saved classifications and sessions remain intact. Existing manual worked-time entry remains governed by its original setting and is not disabled by the timer-module switch. If an admin or group manager starts a tracked ticket assigned to someone else, attribute the timer to that collaborator rather than the manager who changed the status. In the hours report, customer billing status applies to the whole ticket across month filters; collaborator invoice receipt is separate from whether hours are recognizable. Customer-billable tracked tickets require a client; collaborator-recognizable tracked time requires an individual assignee, but non-recognizable tracked tickets may remain unassigned.

**Why:** The user wants the timer to reflect recorded work independently from billing and recognition, and requires operator-facing privacy around those classifications. Admins found the hours report confusing, so its presentation should clearly group client-billable and collaborator-recognizable time separately and explain that billing status is ticket-wide while invoice receipt is separate. Historical sessions must remain trustworthy when admins change future classifications. The organization gate preserves the existing manual workflow. The user also expects distinct collaborators' practices to run concurrently, including when one admin or manager changes both statuses; attributing both sessions to that manager incorrectly trips the one-active-timer-per-user constraint. The user chose ticket-wide customer billing, an independent “Fattura ricevuta” collaborator status, and the rule that assignment is required only when hours are recognizable.

**How to apply:** Gate timer sessions, classification settings, and the dedicated hours report on the organization module without deleting historical data; keep manual worked-time recording and its existing customer report independent. Keep ticket-level client billing shared by all months, and track collaborator invoice receipt independently of recognition. Capture classifications on each new timer session; do not expose them to non-admins. Resolve the timer user from the assigned collaborator when an admin or group manager changes a ticket's status; reject customer-billable tickets without a client and prevent recognizable sessions from starting without an individual assignee.
