---
name: Timer module and manual worked-time scope
description: Product decision separating organization-gated timers from the existing manual worked-time flow.
---

A separate organization-level timer module is disabled by default, and tracked tickets additionally require an explicit per-ticket opt-in. When the module is off, timer, compensation-classification, and report controls are hidden and their API writes are blocked, while saved classifications and sessions remain intact. Existing manual worked-time entry remains governed by its original setting and is not disabled by the timer-module switch. If an admin or group manager starts a tracked ticket assigned to someone else, attribute the timer to that collaborator rather than the manager who changed the status. In the hours report, customer billing status applies to the whole ticket across month filters; collaborator invoice receipt is separate from whether hours are recognizable.

**Why:** The task explicitly requires a separate organization gate while preserving the existing manual workflow. The user also expects distinct collaborators' practices to run concurrently, including when one admin or manager changes both statuses; attributing both sessions to that manager incorrectly trips the one-active-timer-per-user constraint. The user chose ticket-wide customer billing and an independent “Fattura ricevuta” collaborator status.

**How to apply:** Gate timer sessions, compensation settings, and the dedicated hours report on the organization module without deleting historical data; keep manual worked-time recording and its existing customer report independent. Keep ticket-level client billing shared by all months, and track collaborator invoice receipt independently of recognition. Resolve the timer user from the assigned collaborator when an admin or group manager changes a ticket's status; keep the actor as owner when no individual assignee exists.
